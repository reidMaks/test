# ADR 010: Gatus Auto-Discovery via gatus-sidecar

## Status
Accepted

## Context
Our IaaC cluster uses Gatus for uptime monitoring and status pages (`status.kms-lab.in.ua`).
Previously, all monitored services (Paperless, Tandoor, ActualBudget, etc.) were hardcoded in `gatus_config.yaml`.
As the number of workloads grows, statically defining HTTP checks becomes tedious and error-prone. Additionally, some services might be forgotten or misconfigured.

## Decision
We implemented `gatus-sidecar` (`ghcr.io/home-operations/gatus-sidecar`) inside the Gatus Pod to automatically discover Kubernetes `Ingress` resources across all namespaces.
The sidecar watches cluster-wide `Ingress` objects and dynamically generates an `/config/endpoints.yaml` file containing the HTTP monitoring targets.

1. **Auto-Discovery Configuration (Ingress-Only, All Namespaces):**
   - The sidecar container runs alongside Gatus.
   - It is configured with `--auto-ingress` and `--output=/config/endpoints.yaml` (without `--namespace` restriction) so all web-facing `Ingress` resources across `default`, `monitoring`, `longhorn-system`, `headlamp`, `management`, `apn`, and `mcp` are discovered automatically without duplicate TCP `Service` checks.
   - Temporarily scaled-down workloads (`replicas = 0`, such as `open-webui`, `litellm-ui`, `mcpo`, `headroom`, and `freelingo`) are excluded via the `gatus.home-operations.com/enabled: "false"` annotation on their `Ingress` resources so they do not appear as failing endpoints.

2. **Gatus Configuration Merging & Startup Synchronization:**
   - Gatus v5.x expects a single configuration path (`GATUS_CONFIG_PATH`). It does not support comma-separated file lists.
   - We mount an `emptyDir` volume at `/config` for Gatus and the sidecar.
   - An `initContainer` copies the statically defined configuration (from `gatus-config` ConfigMap, which includes alerts and external infrastructure checks) into `/config/config.yaml`.
   - Because Gatus's hot-reload watcher (`HasLoadedConfigurationBeenModified`) compares file `ModTime().Unix()` at 1-second resolution (`lastMod < info.ModTime().Unix()`), starting `gatus` and `gatus-sidecar` in the same Unix second caused Gatus to miss `/config/endpoints.yaml` when the sidecar wrote it ~140ms after Gatus loaded `config.yaml`.
   - Setting `GATUS_DELAY_START_SECONDS: "5"` on the main Gatus container ensures `/config/endpoints.yaml` is already generated by the sidecar before Gatus performs its initial configuration load.

3. **RBAC:**
   - A `ClusterRole` and `ClusterRoleBinding` (`gatus-sidecar`) are granted to the Gatus `ServiceAccount` (`default/gatus`) to allow it to `get`, `list`, and `watch` `ingresses`, `ingressclasses`, `services`, `endpoints`, and `ingressroutes` across all namespaces.

4. **Service-Specific Annotations (`gatus.home-operations.com/*`):**
   - `home-operations/gatus-sidecar` v0.5+ uses `gatus.home-operations.com/enabled` (`"true"` / `"false"`) and `gatus.home-operations.com/endpoint` (YAML snippet merged into the generated endpoint).
   - Endpoints with non-root health paths or non-200 expected HTTP status codes (such as RustFS S3 API/Console using `path: /health` and MCP servers using `/healthz` or `/mcp` under `group: MCP Servers`) are configured via `gatus.home-operations.com/endpoint`.

## Consequences
- **Positive:** We no longer need to manually add internal cluster services across any namespace to the Gatus dashboard. It scales automatically.
- **Positive:** Static checks are restricted only to external home infrastructure (Proxmox, NAS, Portainer, Jellyfin, Radarr).
- **Negative:** Gatus sidecar requires cluster-wide read-only RBAC permissions (`ClusterRole`) to watch `Ingress` resources across namespaces.
